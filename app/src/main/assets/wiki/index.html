Quick start

ValDroid is a launcher: it runs your own copy of Valheim on Android. The game itself is not included.

  1. You need your own copy of Valheim — bought on Steam, for example. ValDroid runs the Linux build of the game.
  2. Get the game into the app: open the side menu and tap Steam Downloads. The game downloads straight into a ready instance. The other way is a .zip archive prepared on a PC.
  3. An instance is one installed copy of the game. It has its own card on the main screen and its own settings behind the gear icon.
  4. When an instance is created, ValDroid detects your phone's GPU and picks a matching graphics driver by itself.
  5. Tap the ▶ button on the card. The first launch takes longer while the game prepares its files. Do not press Back while it loads.

You need Android 11 or newer, a 64-bit phone with an Adreno (Snapdragon) GPU and at least 8 GB of RAM, plus about 8 GB of free storage. Other GPUs are untested.

The ? at the top of each screen opens this page at the part about that screen.

Something went wrong? See Reporting a problem.

Getting the game

ValDroid needs the Linux build of Valheim. The in-app download takes it from the Steam account that has the game; the other way is an archive you prepare yourself.

If you own the game on Steam, that is the easiest way: it downloads right inside the app, updates from the phone without a PC, and saves go through Steam Cloud, shared with your PC — you can continue a PC world on the phone and back.

1. From Steam, in the app

  1. Open the side menu and tap Steam Downloads, tab Game.
  2. Enter a name for the new instance.
  3. Sign in with your Steam account. Your login goes to Steam only and is not stored. Approve the sign-in in the Steam Mobile app, or enter the Steam Guard code.
  4. Tap Download. The newest public build goes straight into a new instance: about 4 GB, so use Wi-Fi. You can switch to other apps meanwhile.
  5. If the download stops, start it again with the same instance name and it continues where it stopped.
  6. When the bar reaches 100% the app packs the game into a backup archive in the Downloads folder. That takes a few more minutes for several GB and needs the app open — it looks like nothing is happening, but it is working. You can delete the archive afterwards if you need the space.

To get an older build instead of the newest one, enter its Manifest ID in the advanced field (the IDs are listed on SteamDB). Otherwise leave it empty.

Updating the game. When a new version comes out on Steam, run the download again with the same instance name: the new build is fetched, and your saves and settings stay where they are. For now this downloads the whole game again, about 4 GB.

2. From a .zip archive

Open the side menu and tap Add game instance, or the + at the top of the main screen. Enter a name, tap Pick ZIP file, choose the archive and tap Install.

  • The .zip must hold the Linux build of Valheim — the one with the valheim.x86_64 file. A folder around it is fine, ValDroid finds it.
  • The Windows version (the one with valheim.exe) will not run — it has to be the Linux version.
  • Keep the internet on while installing: the launcher fetches a small library for the game.
  • On a PC you can make that archive with DepotDownloader: DepotDownloader -app 892970 -depot 892971 -os linux, then zip the result.
  • Keep the name short: Latin letters and digits, up to 40 characters.
  • The archive does not show in "Downloads"? That section lists only files the system knows about, and files put there around it (by adb, Termux or some file managers) may be missing. In the file picker open Internal storage → Download instead — that reads the folder straight from disk. If there is no such entry, turn it on in the picker's menu: Show internal storage.

Picture and frame rate

All of these are in the instance settings (gear icon).

  • Render resolution (its own card) sets the size of the game picture. The choices are shown in pixels for your screen; a smaller one gives more FPS and a bigger interface. Black margins 1280×720 keeps a classic 16:9 picture with bars at the sides.
  • Graphics: the profile with the most FPS is Minimal on the native engine and Very low on the box64 engines, and a new game starts on it. Very low has no tessellation, no shadows and no extra draw distance; Low keeps antialiasing, bloom and sun shafts; Minimal, for weak GPUs, also lowers the 3D picture (pixelated), and on the native engine makes textures 4× smaller and turns realtime shadows off. After that you can tune the graphics in the game's own settings; the launcher no longer touches them. Apply puts a profile back on the next launch; a grey button means it is already set.
  • Textures are reduced automatically: the biggest ones are shrunk to save video memory. There is nothing to set.
  • Shader cache (card Texture compression, on by default) keeps compiled shaders on the phone, so a new enemy or effect stutters only the very first time you see it, not in every session. Turn it off if something renders wrong. It belongs to MobileGlues, like Enable ETC2 compression next to it.
  • In-game display (card Frame rate): Off, FPS (the frame rate in the top-left corner) or Full info (a bar at the top with the frame rate and a graph, GPU and CPU load, memory and temperature).
  • Frame rate limit (card Frame rate): No limit, Economy (~30), Balanced (~40) or Smooth (~60). The exact number is picked to fit your screen and shown under the choice. A steady rate feels smoother than one that jumps, and the phone stays cooler, so it keeps its speed longer.

Set the resolution in the launcher, not in the game: the launcher starts Valheim at the size it chose, so the game's own resolution list has no effect (and shows 0x0). These settings apply to every engine.

Controls

On-screen controls

A new instance starts with the gamepad layout. It drives a virtual Xbox controller, so as far as the game is concerned you are holding a real pad, with the game's own button hints. Valheim's controller interface then handles the inventory, building and menus with buttons, and you never have to aim a cursor at small cells on a phone screen.

  • The Gamepad layout: two sticks, a d-pad, A/B/X/Y, LB/RB, LT/RT, Back and Start, and the stick clicks L3 and R3.
  • The second built-in layout, Keyboard and touchpad, is under Layouts in the editor. It plays with keys and the mouse instead: a WASD stick to walk, a mouse stick for the camera and the cursor, ATK/R (left click: attack), BLK/L (right click: block), ALT (middle click: secondary attack), JUMP, RUN (Shift; it stays on until you tap it again), CROUCH (Ctrl), USE/E, R, F, AUTO (Q, autorun), Esc, INV (Tab), MAP (M) and the hotbar keys 1–8.
  • Both layouts have V, which hides and shows the controls, and KB, which opens the Android keyboard for typing.
  • Keyboard and gamepad elements can be mixed in one layout: the game accepts both at the same time.

Camera and cursor

  • In gameplay the touchpad and the mouse stick turn the camera by as much as your finger moves, and stop as soon as it stops. In menus and the inventory they move the cursor instead.
  • A tap on the touchpad is a left click. It can be switched off in the touchpad's settings (Tap = left click), so a stray tap does not click anything.
  • A physical mouse works for looking around too: in gameplay the app captures it, so the camera turns freely instead of stopping at the screen edge.

Element types

  • Button, rectangle or round. Styles: Outline, Filled and Glass. It can show your own picture (a PNG) instead of text, with Keep original colors if the picture should not be tinted. Toggle makes it latch: one tap holds the key, the next releases it. Bind several keys to one button for a combo.
  • D-pad.
  • Stick: a gamepad stick, or four keys of your choice.
  • WASD stick: presses W, A, S and D.
  • Mouse stick and touchpad: the camera and the cursor.
  • Scroll bar: the mouse wheel.
  • Radial menu: put your finger on the centre and swipe into one of four sectors; each sector has its own action.

Controls editor

In the instance settings (gear icon), card Controls, tap Edit on-screen controls.

  • Tap an element to open its settings: size, opacity (To all applies it to every element), sensitivity, text, toggle, style, picture, the bindings (add and remove them), the input type, and Delete element.
  • Drag an element to move it.
  • Long-press an empty spot, or tap Add, to add an element.
  • Layouts loads one of the two built-in layouts in place of the current one.
  • Background puts a picture behind the layout — a screenshot of the game, for example — so you can place the buttons against it. No BG removes it. The background is only for the editor; the game never shows it.
  • Grid: while it is on, an element snaps to the grid when you let go of it.
  • Done closes the editor. Changes are saved automatically.

Saving and sharing layouts

  • Each instance keeps its own layout.
  • Export controls layout and Import controls layout in the side menu save and load a layout as a .zip, with its pictures inside.
  • Layouts from earlier ValDroid versions cannot be imported: make a new one in the editor.

Physical gamepad, mouse and keyboard

  • A physical gamepad works and feeds the same virtual pad. While one is connected, the on-screen gamepad elements are hidden; keyboard and mouse helper buttons stay.
  • A physical mouse and keyboard work too. Shift stays held while you press and release other keys, so sprinting no longer stops; Backspace, Delete and the arrows repeat when held; the numpad keys, numpad Enter included, work.
  • Every key can be put on an on-screen button, Backspace, comma, period, Ctrl, Alt and Right Shift included.
  • The Android Back gesture or button works as Esc: it opens Valheim's menu instead of closing the game.
  • The game always runs in landscape. Mirror the picture (180°) flips it for a gamepad or cradle that holds the phone the other way up. It applies from the next launch.

Saves

Valheim keeps a world as two files (.fwl and .db) and a character as one (.fch).

  • Export saves and Import saves in the side menu move an instance's saves out and in as a .zip: for a backup, or to carry them to another instance or phone.
  • Steam Cloud saves: if you also play Valheim on a PC through Steam, this brings your cloud worlds and characters onto the phone and sends the phone's back. The sign-in is approved in the Steam Mobile app, so Steam Guard must be on there. When the same name exists on both sides, you choose which one to keep. Close the game before sending.
  • Valheim's cloud is per world and per character: on the PC, a save has to be moved to the cloud in the game's own menu. A save that was never moved there is not in the cloud, and the list will look empty.

Engine

In the instance settings (gear icon), the first card, Engine. It decides how the game runs, and with it which of the other settings apply.

  • Full emulation (box64) — the PC version runs as is, entirely through x86 emulation. The most compatible and the slowest. Mods do not load.
  • box64 + native Mono — the Unity engine is emulated, but the game's own code (everything written in C#) runs directly on your phone's processor. Much faster in busy places; mods work.
  • Native engine (experimental) — nothing is emulated: Unity's own Android engine runs the game. The fastest, and the picture is sharper, because textures are not re-compressed on the way. It appears only in builds that include it.

A new instance starts on the native engine. Instances from earlier versions keep what they used. Saves, the game's own settings, the on-screen controls and the mods are the same for all three, so you can switch at any time and nothing is lost.

Native engine

On most phones it is the best choice: the game loads faster, the frame rate is higher and steadier, and the battery lasts longer than with the box64 engines.

  • It always renders with Vulkan, on the phone's own driver. While it is chosen, the renderer and Vulkan driver (card Video), the shader and ETC2 caches and compatibility mode are greyed out: they do not apply to it.
  • Render resolution, frame rate mode, the performance overlay, the mirrored picture and the on-screen controls work as usual. Textures are always reduced by one step (two on Minimal).
  • The first start after installing or updating ValDroid takes a few seconds longer: the launcher prepares the game data for it (about 100 MB).
  • Mods work, except the parts of a mod that bring their own x86 libraries (.so files): those cannot load without emulation.
  • Here the GPU is the limit, not the processor. If the frame rate drops in heavy scenes, turn off SSAO, point light shadows and sun shafts in the game first.
  • It runs on Snapdragon (Adreno) and Mali GPUs. If the picture freezes on the logo or in the menu while the game goes on, set Vulkan compatibility (card Engine) to On: some Mali drivers lose the GPU without it.

Graphics drivers

The renderer is picked in the instance settings (gear icon), card Video. There are two.

These settings apply to the two box64 engines. The native engine always renders with Vulkan on the phone's own driver.

  • MobileGlues — the default. The game runs on OpenGL, which MobileGlues translates to the phone's own graphics on the fly. No Vulkan is involved at all: your GPU's own vendor driver does the work. On Snapdragon that is roughly twice the frame rate of the Vulkan path, at one settings tier higher. On Mali GPUs it is the only option that works, because no open Vulkan driver exists for them.
  • Zink ZFA — the game runs on Vulkan directly. Slower, but it is the fallback for anything MobileGlues renders wrong or refuses to start.

The settings below belong to Zink ZFA — they choose the Vulkan driver. On MobileGlues they change nothing.

  • When you create an instance, ValDroid picks a driver for your GPU, and Recommended driver (detect GPU) does the same again. If the picture looks wrong or stays black, try another one.
  • Turnip: an open-source driver for Snapdragon (Adreno) GPUs, built for the GPU generation named in the list (6xx, 7xx, 8xx, 830/840). This is the one Valheim was brought up on.
  • System (phone driver): the phone's own driver. It is the only choice on phones without an Adreno GPU, and Valheim on those is untested.
  • Custom driver (imported): your own driver. Import it in the side menu, Custom Vulkan driver (a .so file or an AdrenoTools .zip). It is then shared by all instances.

Mods

Mods are installed per instance: open the side menu and tap Mods.

  • Pick the instance at the top and turn on Mod support (BepInEx): it loads BepInEx when the game starts, and with it the mods switched on below.
  • Mods work with box64 + native Mono and the native engine, not with full emulation (see Engine).
  • To install a mod, tap Choose mod file (zip), pick the .zip and tap Install.
  • Each installed mod has its own switch, to turn it on or off.
  • To delete a mod, tap the trash can on its row and confirm. Any game files the mod replaced are put back.

Advanced settings

In the instance settings, card Advanced (tap its title to open it).

  • Compatibility mode: turn it on if the game will not start — a black screen, or stuck on loading. The game runs a bit slower with it, so leave it off when you do not need it.
  • Debug mode writes a more detailed log.
  • Environment variables is a field for launch settings we may ask you to try. Leave it empty unless you are testing something.

Getting the best performance

The whole Unity engine is emulated, so the processor is the limit, not the GPU. Anything that adds objects or passes to a frame — shadows, tessellation, draw distance, vegetation — costs far more than resolution or texture size.

This is about the two box64 engines. With the native engine nothing is emulated and the GPU is the limit instead: lower the heavy effects (SSAO, point light shadows, sun shafts) first.

  • Check your phone's performance profile first. On Samsung, a profile such as Light in Battery settings caps the processor and the GPU to roughly half their speed, and that alone can halve the frame rate. Set it to Standard, and turn on the phone's game booster for ValDroid: Samsung Game Booster, Xiaomi/POCO Game Turbo, Realme/OPPO/OnePlus Game Space, vivo/iQOO Ultra Game Mode, Infinix/Tecno Game Mode.
  • Use the Graphics preset (its own card). If you prefer to set things in the game yourself, the one thing to turn off first is tessellation.
  • Lower the Render resolution — the sizes are listed in pixels; the middle ones are a good balance — and set a Frame rate limit so the rate stays steady instead of swinging.
  • The phone heats up, and every phone slows itself down when it does. A cool phone can be noticeably faster than the same phone twenty minutes later; a case off and a cool room help more than they sound like they would.
  • Close background apps, especially other games and browsers.

Known issues

The resolution list in the game shows 0x0

Expected. The launcher starts the game at the size of its own window, and that size is not one of Valheim's standard modes. Change the resolution with Render resolution in the instance settings instead; the list inside the game does nothing.

Crackling sound under load

Sound can crackle while the game is loading or during heavy scenes. It settles down once the scene is loaded. Not fixed yet.

Black screen after starting the game again

If you leave the game while it is still running and then tap ▶ again, the screen can stay black. Return to the running game from the recent-apps screen instead. If it is already black, close ValDroid completely (swipe it away in recent apps) and launch again.

Picture cut off at both sides (OPPO and other ColorOS phones)

The per-app display setting Hide camera shrinks the game and cuts off both sides. Fix: turn Hide camera off for ValDroid, keep Full screen on, close the app completely and launch again. The names of these settings vary between phones; search the phone's settings for "full screen".

Phones without an Adreno GPU

Valheim was brought up on Snapdragon (Adreno) phones first. It now runs on Mali too, best on the native engine. On other GPUs it may not start, or the picture may be wrong. Please send a report with Report a bug.

Black ground on some Mali GPUs

On some Mali GPUs (the Mali-G615, for example) the ground can render black. We are working on it. Please send a report with Report a bug: it helps us fix it.

Reporting a problem

Open the side menu and tap Report a bug, then choose the instance where the problem happened. ValDroid attaches its logs, your graphics settings and your phone's details to a message to us: pick your email app, describe the problem and tap Send. Report right after the problem happens, while the log still holds it.

The icons at the top of the side menu lead to new versions on GitHub and to the author's X and Reddit.
